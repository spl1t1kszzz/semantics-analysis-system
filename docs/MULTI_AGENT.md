# Мультиагентная архитектура извлечения отношений

## Мотивация

Базовый пайплайн извлекает для каждой пары терминов **одно** отношение через свободный промпт «какое отношение?». LLM выбирает один предикат, и если пара терминов не подходит ни под один предикат, модель иногда ошибочно отвечает «нет отношения». При этом целенаправленный бинарный вопрос «есть ли конкретно это отношение?» может дать другой (верный) ответ.

Мультиагентный подход использует **multi-probe как fallback**: если стандартное извлечение не нашло отношения, запускается multi-probe — бинарный вопрос «да/нет» по каждому предикату. Это позволяет:
- **дополнить recall**: поймать отношения, пропущенные стандартным методом;
- оценивать каждый предикат **независимо**, без конкуренции с другими;
- **разрешать конфликты** (несколько «да») через отдельный LLM-агент.

## Архитектура

```
                    Текст + Термины
                          |
                          v
              +-----------------------+
              |  Стандартное           |   (LLMRelationExtractor)
              |  извлечение           |
              |                       |   detect_predicates():
              |  Свободный промпт     |   «какое отношение между A и B?»
              |  с few-shot примерами  |
              +-----------------------+
                          |
                 Найдено? ----ДА----> verify_relation() ---> Relation
                          |
                         НЕТ  (стандарт ничего не нашёл)
                          |
                          v
              +-----------------------+
              |   Multi-probe         |   (fallback)
              |   агент-экстрактор    |
              |                       |   detect_predicates_multi_probe():
              |  Бинарный «да/нет»    |   по каждому предикату независимо
              |  по каждому предикату  |
              +-----------------------+
                          |
                 Найдено? ----ДА----> verify_relation() ---> Relation
                          |
                         НЕТ ---> нет отношения
                          
                          ... (для всех пар терминов)
                          |
                          v
              +-----------------------+
              |  Детектор конфликтов   |   (detect_relation_conflicts)
              |                       |
              |  Группирует по паре   |   -- находит пары с >1 предикатом
              |  (term1, term2)       |
              +-----------------------+
                          |
                  конфликтные группы
                          |
                          v
              +-----------------------+
              |   Агент-резольвер     |   (RelationConflictResolver)
              |                       |
              |  Верифицирует каждое   |   -- re-verify через verify_relation
              |  отношение в группе   |      оставляет подтверждённые
              +-----------------------+
                          |
                          v
                 Relation[] (финальный результат)
```

## Компоненты

### 1. Стандартное извлечение + Multi-probe fallback (`LLMRelationExtractor`)

**Файл:** `semantics_analysis/relation_extraction/llm_relation_extractor.py`

Для каждой пары терминов, допустимой по онтологии:

**Шаг 1 — стандартное извлечение** (`detect_predicates()`):
1. Формирует промпт с rich few-shot примерами из онтологии
2. Просит модель выбрать подходящий предикат (или «нет»)
3. Парсит ответ — ищет имена предикатов

**Шаг 2 — multi-probe fallback** (`detect_predicates_multi_probe()`):
Запускается **только если** стандартное извлечение не нашло ничего.
1. Формирует промпт с **бинарным вопросом «да/нет» по каждому предикату**
2. Один LLM-вызов
3. Парсит ответ: для каждого предиката проверяет «да» рядом с его именем
4. Возвращает все предикаты с ответом «да»

**Шаг 3 — верификация** (`verify_relation()`):
Каждый кандидат (из стандартного или fallback) проходит верификацию через отдельный LLM-вызов с описанием семантики отношения из онтологии.

**Почему fallback а не замена:** стандартный промпт с rich few-shot примерами точнее для большинства пар. Multi-probe лучше ловит отношения, которые стандартный метод пропускает (бинарный вопрос проще для модели, чем выбор из списка).

**Формат multi-probe промпта:**
```
Для каждого отношения ниже ответь «да» или «нет»:
1. isUsedIn — метод используется в науке
2. hasAuthor — метод создан автором
...
Ответ:
1. isUsedIn: <да/нет>
2. hasAuthor: <да/нет>
```

### 2. Детектор конфликтов (`detect_relation_conflicts`)

**Файл:** `semantics_analysis/multi_agent/conflict_resolution.py`

Группирует извлечённые отношения по ключу `(class1, value1, class2, value2)`. Если для одной пары найдено больше одного предиката — это конфликт.

```python
# Пример конфликта:
# ("Method", "BERT", "Task", "NER") -> ["solves", "isUsedForSolving"]
# Два разных предиката для одной пары -> конфликт
```

### 3. Агент-резольвер (`RelationConflictResolver`)

**Файл:** `semantics_analysis/multi_agent/conflict_resolution.py`

Для каждой конфликтной группы (пара терминов с >1 предикатом):

1. Проверяет каждое отношение через `reverify_callback` (= `verify_relation`)
2. Оставляет только подтверждённые отношения
3. Если ни одно не подтверждено — сохраняет все (лучше FP, чем потерять TP)

**Примечание:** на практике конфликтов мало (обычно 0–2 на 100 предложений), поскольку и стандартное извлечение, и multi-probe fallback редко дают несколько предикатов для одной пары. Основной вклад в улучшение метрик вносит multi-probe fallback, а не разрешение конфликтов.

## Конфигурация

```yaml
app-config:
  llm: 'qwen2.5:7b'                   # Модель LLM
  use-multi-agent: true                # Включить multi-probe fallback + конфликты
  use-conflict-dialogue: true          # Двухшаговый диалог при разрешении конфликтов
  use-reverify-after-resolve: true     # Реверификация после разрешения конфликтов
```

При `use-multi-agent: true` включается:
1. **Multi-probe fallback** — для пар, где стандартное извлечение не нашло отношения
2. **Разрешение конфликтов** — для редких случаев, когда для одной пары найдено >1 предиката
